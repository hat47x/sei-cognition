# SEI Brand World — Product Value Discovery Source

更新日: 2026-09-14  
状態: **Non-normative Product Value Discovery Source**

## 1. この文書の役割

この文書は、SEI Cognitionのブランド設計を通して形成されてきた「井」の世界観を、広告コピーやVisual Identityの説明だけへ閉じず、今後のProduct Value探索へ利用できる原資料として保存します。

ここに書かれた象徴は、Product Value、Requirement、Universal ontology、Architecture、UI仕様の正本ではありません。ブランド世界は、現在の設計からは見えにくい問いを開き、利用者や組織にとって何が大切かを別の角度から考えるための**探索源**です。

```text
Brand world
  = discovery source
  != Product Value authority
  != Requirement authority
  != Universal ontology
```

したがって、「井」「水」「深層」「余白」「静けさ」等の語から、型、field、workflow、screen、storage structureを直接導きません。Productへ反映する場合は、必ず利用者benefit、failure、counterexample、既存Valueとの関係へ戻します。

## 2. 井 — 答えを作る中心ではなく、深部へ近づくための境界装置

井戸は水を作りません。地下の水脈そのものでもありません。人が生活する地上と、普段は直接見えない地下との間に、繰り返し利用できる接点を設けます。

この構造をSEIへ重ねると、SEIを「すべてを知り、すべてを考える中央の頭脳」として捉える必要がないことが見えてきます。

SEIが接続し得る深部には、完成済みの答えが置かれているとは限りません。そこには、まだ十分に言語化されていない観察、弱い兆候、経験の断片、違和感、忘れかけた記憶、相反する見方、未検証の関係、Unknown、可能性などが混在し得ます。

SEIの役割をこの比喩から考えるなら、それらを権威的に「真実」へ変換することではなく、**来歴や不確実性を失わず、問い直し可能な認知対象として扱えるところまで表層へ持ち上げる条件を整えること**にあります。

```text
already visible / already articulated
                ↑
              SEI
                ↑
weak signal / unresolved / latent material
```

この上下関係は固定pipelineを意味しません。同じObservationを後から再解釈することも、表層のDecisionが新しい問いを生み再び深部へ向かうこともあります。

## 3. 中央の空白 — 全知のcoreではなく、問いを置けるaperture

井桁の造形では、線そのものだけでなく、その線によって囲まれる中央の空白に意味があります。

この空白を、何もない欠落としてではなく、まだ答えが決まっていない問い、複数の解釈が共存する余地、次の観察を受け入れる入口として読むことができます。

SEIの中心に、常に答えを生成する万能AIを置く必要はありません。むしろ、分からないことを分からないまま保持し、必要な主体が異なる角度から近づき、十分な根拠が整ったときにDecisionへ進める**認知上のaperture**を耐久的に持つ方が、現在のProduct Valueと整合します。

ただし、「余白」はDecisionの回避ではありません。

```text
not forcing premature closure
  != refusing necessary decisions
```

期限、Responsibility、Authority、影響度等によってDecisionが必要な場面では、未解決を消さずに判断し、何を未解決のまま受け入れたかを後から読めることが重要です。

## 4. 水 — KnowledgeではなくCognitive Potential

水をKnowledgeの象徴として固定すると、「地下には完成済みの正解があり、SEIがそれを汲み上げる」という世界像になりやすくなります。

本ブランド世界では、水をより広く**Cognitive Potential**として読みます。

Cognitive Potentialには、たとえば次が混在し得ます。

- observationになる前の弱いsignal
- 個人の経験や記憶の断片
- まだ問いになっていない違和感
- Hypothesis候補
- 相互にConflictする見方
- 未発見の関係候補
- 再利用可能かもしれない過去のMethod / Artifact
- まだEvidenceとして評価されていない情報

汲み上げられたものは、自動的にTruth、Evidence、Recommendation、Decisionにはなりません。

この比喩のProduct上の意味は、新しい`CognitivePotential`型を作ることではなく、**未確定なものを未確定なまま扱える製品であるかを問い続けること**です。

## 5. 静けさ — 反応の遅さではなく、認知帯域を不用意に奪わないこと

SEI CognitionのVisual Worldでは、巨大なAI脳、常時点滅するcommand center、全知のeyeのような表現より、静かな水面、弱い波紋、深さ、余白を重視します。

この静けさは、単なるaestheticで終わらせる必要はありません。

Productとしての静けさは、次のような態度として解釈できます。

- Unknownを埋めるためだけに推測を大量生成しない。
- Conflictを最新値へ急いで畳まない。
- AI suggestionを量そのもので価値化しない。
- NotificationやRecommendationで利用者のattentionを常時占有しない。
- 重要でないdetailを最初から要求しない。
- 必要になったときには、深いbasis、Provenance、historyへ降りられる。
- 高い新奇性やEvidence不足の場面では、流暢な回答より「まだ分からない」を選べる。

```text
quiet
  != passive
  != slow
  = cognitive pressure is justified, not habitual
```

一方、proactive assistanceが大きな価値を生む場面まで静けさを理由に抑制してはなりません。重要なConflict、reopen condition、materialな変化、安全上のsignal等は、適切な強さで利用者へ届く必要があります。

したがって「Quiet Infrastructure」は、常に控えめなUIという仕様ではなく、**attention burdenとproactive valueのtrade-offを明示して設計するためのProduct hypothesis**です。

## 6. 四方向性 — 固定分類ではなくShared Accessibility

井桁の四方向を、Human / AI / Data / Methodのような固定4分類へ割り当てません。

四方向性は、中央へ一方向からしかアクセスできない構造ではなく、異なる主体や情報源がそれぞれの役割を保ったまま同じ認知基盤へ近づける**Shared Accessibility**の象徴として読みます。

接続主体には、人間、AI、Cognitive Method、Document、System、外部Provider、将来の自分などがあり得ます。

ただし、sharedであることはunboundedであることを意味しません。

```text
shared cognition
  != public-to-everyone
  != authority-for-everyone
```

Selective Disclosure、Product Access、Responsibility、Authority、Provenanceを保ったまま、許された主体が同じ認知資産へ戻れることが重要です。

## 7. Cognitive Commons — 私有状態に閉じないが、無境界にも開かない

AI利用が広がるほど、多くの認知成果は一つのchat thread、一人の担当者、一つのmodel context、一つのSaaS内部に閉じやすくなります。

SEIの世界観から見える一つの問いは、それらを組織や個人の**durable cognitive resource**へ変えられるか、というものです。

ここでいうCognitive Commonsは、法制度としてのcommonsや全社公開を意味しません。より限定して、次の状態を指す探索語です。

- 認知成果が特定sessionの寿命だけで消えない。
- Provenanceと意味差を保って後から再利用できる。
- 別の人間やAIが、許可された範囲で問い直せる。
- 一つのProviderを失っても利用可能性が残る。
- accessできることからDecision Authorityを推定しない。

Cognitive Commonsが独立したProduct Valueなのか、Human / AI Readability、Provider Independence、Decision Continuity、Product Access等の横断的な利用状態なのかは、別途Reviewで判断します。

## 8. Human / AI / Method / Systemは井を利用する主体であって、井そのものではない

SEIを「AI脳」として描くと、現在のmodel能力を製品identityへ焼き付ける危険があります。

SEIは、AIが高度化してもAIそのものと同一化しません。人間、AI、Method、System、Document、History等が、それぞれ異なる責任とCapabilityを持ちながら認知基盤へ接続します。

```text
Human ─────┐
AI ────────┤
Method ────┤
Document ──┼── SEI Cognition
System ────┤
History ───┘
```

AIは非常に重要な利用主体・Provider・Method realizationになり得ますが、SEIの意味上の中心を独占しません。

## 9. SEI / SUI / TEI — 象徴的な関係であって固定pipelineではない

関連製品群では、易の卦を機械的な分類体系ではなく、各ソフトウェアの位置づけを考える象徴層として利用できます。

現時点では、次のような読みが可能です。

```text
井 / SEI Cognition
  depth / access / cognition

萃 / SUI Sensemaking
  gathering / relation / emergence

鼎 / TEI
  transformation / realization / execution
```

この関係は、次のような循環を想像する補助線になります。

```text
まだ十分に形を得ていないもの
        ↓
SEI: 認知可能な素材として扱える条件をつくる
        ↓
SUI: 集め、関係を見いだし、共有可能な構造を育てる
        ↓
TEI等: Intentを実現可能なCapabilityへ接続する
        ↓
現実世界の変化
        ↓
新しいObservation / Questionとして戻る
```

実際の利用では順序は固定されません。SEI単独で完結する場合も、SUI以外のSensemaking Methodを使う場合も、TEI以外のProviderへ実行を委ねる場合もあります。

```text
symbolic affinity
  != required dependency
  != preferred Provider
  != Universal workflow
```

## 10. ブランド世界から直接導いてはいけないもの

この世界観は豊かな探索源ですが、次を直接正当化しません。

- `Well`、`Water`、`Depth`等のUniversal型
- 4種類に固定したactor taxonomy
- 地下／地上の二層storage architecture
- 常に静かなUI
- AI suggestionの抑制を固定したpolicy
- SUI / TEIの必須利用
- 特定のロゴ形状から導くscreen layout
- 「深層」に正しい答えがあるという認識論
- 「無意識」に関する心理学的・医学的主張

Productへ採用するのは象徴そのものではなく、象徴が照らした**利用者世界の持続的なbenefit / failure**です。

## 11. 対立する読みを残す

ブランド世界を一つの解釈へ閉じないため、少なくとも次の対立を今後も保持します。

| 一方の読み | 反対側の問い |
|---|---|
| 深層へアクセスする | 既知の判断を正確に保持する方が重要な場面もある |
| Cognitive Commons | privacy / bounded accessを損なわないか |
| 静かな基盤 | proactive assistanceを弱めないか |
| 非収束性 | Decision latencyや責任回避につながらないか |
| 余白を守る | structure不足で再利用不能にならないか |
| shared cognition | Responsibilityが曖昧にならないか |
| 象徴的一貫性 | 実際のProduct differentiationがあるか |

SEIのProduct Valueは、この対立を隠すのではなく、実際のScenarioとEvidenceへ戻って選び直せる必要があります。
