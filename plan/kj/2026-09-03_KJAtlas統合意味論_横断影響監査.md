# KJ Atlas統合意味論のSOZA横断影響監査

更新日: 2026-09-03  
状態: Current cross-repository impact review

## 1. 監査の目的

KJ Atlasの`AI-MERGE-SEMANTICS-01`では、カードの統合支援について、04ステップによる近接カードの整理と、核融合法による意味核の統合を使い分ける方針が具体化された。

SOZAはCognitive Methodとその適用結果を長期的に参照・交換する意味基盤を持つため、この変更がSOZAのUniversal Contractへ波及するかを確認する。

本書はKJ working recordとして影響判断を残すものであり、Accepted ADRやContractそのものではない。

## 2. 確認したSOZAの現行境界

`SOZA Cognitive Method Contract v1alpha1`は、次を明示的に分離している。

```text
Method Definition
  != Method Realization
  != Method Application
  != Recommendation
  != Decision
  != Assurance
```

Method Applicationは、必要に応じて`input_refs`、`output_refs`、`residual_refs`、`provenance refs`を持てる。また、改訂・来歴はSemantic Reference ContractのLogical Reference / Exact Binding / Semantic Lineageを再利用できる。

このため、外部ツールがあるMethodをどのようなAPI・UI・proposal形式で実現するかは、Method Definitionの必須構造ではない。

参照:

- `contracts/cognitive-method/SOZA_COGNITIVE_METHOD_v1alpha1.md`
- `contracts/semantic-reference/SOZA_SEMANTIC_REFERENCE_v1alpha1.md`

## 3. KJ Atlas側の変更をどう受け取るか

KJ Atlasで具体化された次の要素は、SOZAのUniversal Method Definitionへ直接追加しない。

- 04ステップ型／核融合法型を区別するKJ Atlas固有の提案種別。
- `mergeMethod`等の将来のAPI field名。
- KJ Atlas固有のproposal responseやUI操作。
- `repOf` / `canonicalId` / `mergedIntoCardId`等をそのままSOZA Universal fieldへ写すこと。

これらは必要に応じて、KJ AtlasというMethod Realizationのimplementation Artifact、または特定のMethod Applicationにおけるinput / output / residual / provenanceの参照として扱う。

KJ Atlasの製品語彙をSOZAの普遍語彙へ昇格させるには、KJ Atlas以外のRealizationでも共通して必要であることと、既存Semantic Reference / Lineageでは表現できない具体的欠落の両方が必要である。

## 4. source・residual・lineageの整合性

KJ Atlas側の統合意味論では、元カード・出典・残差・統合系譜へ戻れることが重要な不変条件になっている。

SOZA側でも、Method Applicationの`input_refs` / `output_refs` / `residual_refs`とSemantic Lineageを使えば、少なくとも意味契約上は次を分離できる。

```text
source cards / source artifacts
  → Method Application input

integrated proposal / integrated artifact
  → Method Application output

unabsorbed difference / held conflict / exception
  → residual reference

historical identity / revision / derivation
  → Semantic Reference / Lineage
```

したがって、2026-09-03時点ではContract schemaの追加変更を要求しない。

ただし、実際のKJ Atlas→SOZA取り込みAdapterで、次のいずれかが失われる場合は別Issueを起票する。

1. 元カードへの参照。
2. 統合後に残した残差・保留・対立。
3. 統合前後の由来関係。
4. どのMethod Realizationで生成されたかというExact Binding。
5. proposalであることと、人間が採用したDecisionであることの区別。

## 5. cultural-substrate-weavingとの関係

cultural-substrate-weavingは、KJ Atlasの製品固有のRealizationを方法論正本へ自動的に取り込まない方針である。

SOZAも同じ境界を維持する。cultural-substrate-weavingのMethod Definitionと、KJ Atlasでの具体的なRealization / Applicationを分離して参照できることが、現行Cognitive Method Contractの役割である。

参照:

- `hat47x/cultural-substrate-weaving:docs/ja/maintainers/kj-atlas-merge-semantics-boundary.md`
- `hat47x/kj-atlas:01_Plans/cross-repo/2026-09-03-kj-merge-method-boundary.md`

## 6. TEIへの影響

今回のKJ Atlas変更は、SOZAが外部Capability Providerへ委譲するExecution、Binding、Runtimeの契約を変更しない。

したがってTEI側には対応変更を要求しない。将来、KJ Atlasの統合操作そのものをTEI Capabilityとして実行させる、またはKJ Atlasの統合成果をTEIのCanonical Semanticへ直接受け渡す具体的要件が成立した場合にのみ、SOZA / TEI境界を再監査する。

## 7. 現在の判定

2026-09-03時点の判定は次のとおり。

- **SOZA Cognitive Method Contract: 変更不要。**
- **Semantic Reference / Lineage: 変更不要。** 現行契約で必要な由来関係を表現できると判断する。
- **KJ Atlas Adapter: 現時点では変更要求なし。** 実取り込みでlossが観測された場合に起票する。
- **cultural-substrate-weaving: Method DefinitionとKJ Atlas Realizationを分離して扱う。**
- **TEI: 変更なし。** Capability / execution契約への具体的波及はない。

この「変更不要」は、外部変更を無視した結果ではない。現行SOZA契約が、MethodとRealizationを分離することで外部実装の進化をすでに受け止められることを確認した結果である。

## 8. 次回の横断確認条件

次のいずれかが生じたとき、本監査を再開する。

- KJ Atlasで統合proposalの永続表現が確定し、SOZA取り込みAdapterを実装するとき。
- source / residual / lineageのいずれかが現行Contractで表現できない実例が出たとき。
- cultural-substrate-weavingのMethod Definition自体が、KJ Atlas dogfoodを根拠に変更されたとき。
- TEI Capabilityとして統合操作を公開する要求が生じたとき。

それまでは、新しいUniversal fieldやContract versionを先回りして追加しない。
